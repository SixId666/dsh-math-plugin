### 2.1 L1 端到端验收测试 `tests/_test_acceptance.py`（656 行）

- 入口：`E.execute(op, args)` —— 与插件运行时同一条调用路径，不额外 mock。
- 断言：`check(name, op, args, predicate, group, note)`，`predicate` 收到引擎 payload；失败时保留 payload 前 1500 字符。`run()` 捕获异常、**永不抛出**，异常也计入失败而不是中断全部用例。
- 比较器（关键设计，避免「假失败」）：
  - `equal_value(payload, expected, tol=1e-9)`：精确式优先、必要时按容差、**无穷单独分支**（`_INFINITIES = (sp.oo, -sp.oo, sp.zoo)`，注释原文「±∞ 相减会得到 nan，绝不能走减法路径」）、布尔分支、矩阵/列表逐元素分支（含维度检查）。
  - `verified(payload)`：要求至少一条验证方法，且**不存在** `passed is False` 或 `agree is False` 的条目；注释说明「引擎里确有 `passed=None` 的条目，只认显式判否」。
- 分组与调用方式：`GROUPS = {"calculus","linalg","probability","multivar","numeric"}`，支持 `python -X utf8 tests/_test_acceptance.py calculus` 与 `--list`；结尾打印 `通过 N / M   跳过 K`，并把 `{"pass","fail","skip"}` 写入 `E:\dsh-math\tests/_test_acceptance_result.json`。
- 路径解析（第 29–35 行）：在 `HERE/engine` 与 `HERE` 中查找含 `mathkit` 的目录后插入 `sys.path`；找不到则 `SystemExit("找不到 mathkit 包（应在 <repo>/engine/mathkit 下）")`。因此该脚本**可从仓库根目录直接运行**。

#### 2.3.1 `engine\_selftest_verifier.py` 验证的是「验证机制」而非重复计算

该脚本文件头写明：走 Node 侧同一条调用路径 `engine.execute(算子名, 参数)`；每条用例断言 —— status 不是 error、`passed` 与预期一致、验证等级符合预期、**反例必须带差异证据（不允许只有 False 而没有证据）**、**证据不足时绝不允许 `passed=True`**。它检查的失败模式（`run_case` 的 `problems` 判定项 + 45 条用例）：

| 失败模式 | 检查项 | 具体用例（真实存在于脚本中） |
| --- | --- | --- |
| 候选解不满足原方程却判「通过」 | 反例 `passed=False` + `needs_counterexample` | 导数 `x²→x`、恒等式 `x²→x³`、方程解 `→3`、定积分 `→1/4`、归一化解 `→1`、矩阵求逆给错、`sin(x)/x ≠ 0`、`P(X≤3) ≠ 0.5`、`E[X] ≠ 1`、展开给错 —— 共 10 条 |
| 数值与符号不一致却判「通过」 | 同 `needs_counterexample`（要求 `numeric.agree is False` 且带 note，或 deviation/independent_note 键） | 同上反例集合，证据收集见 `_has_counterexample()` |
| 无法验证时谎称 `ok` | `op_status="unsolved"` + `level_in={"none"}` + **`must_not_pass=True`**（若 `passed=True` 记为「严重违规」） | 4 条：复数分支 `log(-x)` vs `log(x)`（符号不收敛且取不到实数抽样点）、只给 `candidate` 没给原始表达式（要求提示含「没有给出原始表达式」）、未知 kind、统计假设条件无法纳入证明（要求提示含「正态」） |
| 未知 `kind` 被静默放过 | `unhandled_contains="未知的计算类型"` | 「未知 kind 必须退化为通用复核」 |
| 正常计算被误判为「未验证」 | 正例 `passed=True` 且 `level="symbolic"` | 18 条：x²→2x、x·e^{x²}、方程、恒等式、矩阵求逆（证据键 `difference_MC_minus_I`）、行列式（`independent_determinant`）、特征值、归一化（`check_expression`）、极限、定积分、化简、因式分解、展开、期望、方差、概率、`sqrt(x²)` 的条件、`1/x` 与 `log(x)` |
| 条件判定错误 | `COND_CASES` 6 条 | `log(x)` 与 `x>0` 相容；`log(-x)` 与 `x>0` **不相容**；`1/x` 与 `x≠0` 相容；「A 可逆」与 `det(A)=0` **不相容**；统计类条件→`unknown/passed=None`；恒真条件 `x²+1>0` |
| 定义域判定错误 | `DOMAIN_CASES` 7 条 | `1/(x-1)@1`、`log(x)@-1`、`tan(x)@π/2`、`asin(x)@2` 均不合法；`sqrt(x)+log(x-1)@2`、`sqrt(x)@1/2` 合法；不给点只给自然定义域必须 `passed=None` |

合计 18 + 10 + 4 = 32（`CASES`）+ 6（`COND_CASES`）+ 7（`DOMAIN_CASES`）= **45 例**，与日志里的「用例总数: 45」一致。**结论：这一层回答的是「验证器会不会把对的判错、把错的判对、把说不清的硬说成对」，与 L1/L2 的「算得对不对」是两件事。**

## 五、测试中发现并修复的真实缺陷

### 5.1 引擎侧缺陷（现象 → 根因 → 修复）

**缺陷 1：关系运算符静默变成「未定义函数」，导致不等式算子直接报「不是不等式」**

- **现象**：`inequality`（不等式分析）对 `x >= 0`、`x <= 1`、`x != 0` 这类输入直接报「不是不等式」；`tests/_test_acceptance.py` 中「不等式分析 x²-1 ≥ 0 的解集」用例无法通过。
- **根因**：`E:\dsh-math\engine\mathkit\ast.py:190` 的
  `_RELATION_BUILDERS = {"==": "Eq", "!=": "Ne", ">=": "Ge", "<=": "Le", "=": "Eq"}` 会把 `>=`/`<=`/`!=` 改写成 `Ge(...)`/`Le(...)`/`Ne(...)`，而 `_RESERVED`（`ast.py:53-70`）原先**只登记了 `Eq`**。于是 `Ne/Ge/Le` 被 SymPy 当作**未定义函数**解析：`x >= 0` 变成未定义函数应用 `Ge(x, 0)`，`isinstance(..., sp.Rel)` 为 `False` ⇒ 不等式判定失效。
- **修复**：把 `"Ne", "Ge", "Le", "Gt", "Lt"` 加入 `_RESERVED`。当前 `ast.py:66` 实际内容：
  `"factor", "series", "subs", "Eq", "Ne", "Ge", "Le", "Gt", "Lt",`
- **旁证（同类坑的先例）**：`ast.py:48-52` 注释记录了另一处保留名缺失造成的错误 —— `Symbol('diff')` 会盖住 `sp.diff`，导致 `TypeError: can't multiply sequence by non-int of type 'Symbol'`。
- **现网验证**：我亲测 `inequality x^2-1 >= 0` → `status=ok`，并带 1 条「解集内/外抽样点代入检验」且 `agree=True`；acceptance 该用例通过。

**缺陷 2：幂级数 `Σx^n` 曾报 unsolved，且数值复核产生「假不一致」**

- **现象**：`sum x^n (n≥1, ∞)` 返回 unsolved（尽管存在闭式 `x/(1-x)`，收敛域 `|x|<1`）。
- **根因**：两点叠加 ——（a）`series_sum` 未处理 SymPy 返回的 `Piecewise`，把「主分支 + 收敛条件」的整体当成未求出；（b）数值复核固定取 `x = 8/5`，该点**落在收敛域之外**，级数发散，于是数值与符号必然不符，被误报成「符号结果与数值结果不一致」。
- **修复**（当前代码事实）：
  - `E:\dsh-math\engine\mathkit\calculus.py:1364-1374`：注释原文「SymPy 返回 Piecewise((主分支, 收敛条件), (Sum(...), True))…绝不能因为『带条件的闭式』就当成未求出而丢掉整个结果」，实现为跳过 `BooleanTrue` 分支并取 `is_closed_form(branch)` 作为主分支；`branch_condition` 记录收敛条件；仅当仍非闭式时才 `MathResult.unsolved`。
  - `calculus.py:1397-1402`：把收敛条件写入 `conditions` 并 `add_warning`。
  - `calculus.py:386-405` 新增 `_series_param_sample(params, condition)`：docstring 原文「幂级数在有收敛域（如 Abs(x) < 1）时，若随手取 x = 8/5 去数值求和，级数在该点发散，数值证据必然与符号结果不符 —— 会把『样本点取在收敛域外』误报成『符号结果与数值结果不一致』」；实现遍历候选样本并用 `sp.simplify(condition.subs(subs))` 过滤，取不到返回 `None`；调用点 `calculus.py:425-428` 此时返回 `("unknown", "级数含参数且取不到满足收敛条件的数值样本，未做数值核验（避免在收敛域外取样导致假『不一致』）")`。
  - 另 `calculus.py:416-418` 注释记录了旧实现用符号部分和（N=51200 时 polygamma 单项 >30s）会拖成假超时，故改用 `mpmath.nsum`。
- **现网验证（亲测）**：`sum x^n (n≥1,∞)` → `status=ok`、`text=x/(1 - x)`、`warnings` 明示「已取主分支 x/(1 - x)，其成立范围为 Abs(x) < 1」、数值方法 `agree="equal"`。

**缺陷 3：`implicit_diff` 的 `vars` 顺序歧义**

- **现象**：`vars = [自变量…, 因变量]` 是隐式约定，调用方把顺序写反时无法报错，求导结果会静默错误。
- **根因**：算子只接受位置化 `vars`，没有显式角色；`x^2+y^2=1` 求 `dy/dx` 与求 `dx/dy` 仅靠顺序区分。
- **修复**：`E:\dsh-math\engine\mathkit\symbolic_extra.py:1177-1199` 新增 `_apply_implicit_roles(names, dependent, independent)`，docstring 原文「调用方常常把 vars 顺序写反…显式给 dependent/independent 即可无歧义地指定角色，且当指定的变量不在 names 里时保持原样（宁可报『变量不足』也不静默换算）」；配套错误文案：`因变量 {dep!r} 不在变量列表 {names} 中`、`自变量 {ind!r} 不在变量列表 {names} 中`、「因变量与自变量不能是同一个变量」。算子签名（`symbolic_extra.py:1202-1209`）新增 `dependent=None`、`independent=None`，调用点 `symbolic_extra.py:1239`。
- **现网验证**：acceptance 两条隐函数求导用例（位置化 `vars`、显式角色）均 `status=ok`；我亲测显式角色调用 `status=ok`（验证方法见第六节观察项）。

**缺陷 4：测试脚本自身的比较器缺陷（`tests/_test_acceptance.py`，导致「假失败」）**

- **现象**：±∞ 期望值的用例（如 `1/x` 在 `x→0⁺` 得 `+∞`）判为失败；矩阵/布尔期望值判为失败；引擎判否字段读不到。
- **根因**：（a）用减法比较无穷会得到 `oo - oo = nan`；（b）矩阵、布尔无法用标量比较；（c）引擎的判定字段既有 `passed` 也有 `agree`，只认其中一个会漏判。
- **修复**：`equal_value()` 增加 `_INFINITIES` 分支（注释原文「±∞ 相减会得到 nan，绝不能走减法路径」）、矩阵/列表逐元素分支与布尔分支；`verified()` 同时识别 `passed` 与 `agree`，且**只把显式 `is False`** 视为否（`None`/缺字段按中性处理，避免 `passed=None` 造成误判）。我亲测确认引擎确实存在 `passed=None` 的条目（如 `inv`/`det`/`eigen` 的方法只给 `agree`），也存在 `method` 为**纯字符串**的条目（`numeric` 的两条路线名）—— 这两点正是该缺陷的真实来源。

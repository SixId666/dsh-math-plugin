## 1. 发布 Release 资产（已完成；以后发版照此流程）

**当前状态**：`v1.0.3` 已发布，资产 `dsh-math.tgz` 与本地 `_dist/dsh-math-1.0.2.tgz`
逐字节一致（sha256 `90A1E04D…57750E`，33 个条目，含 `package/package.json`）。

以后发新版：

```powershell
cd E:\dsh-math
git push origin main
git tag v1.0.4          # 必须是没用过的新 tag 名
git push origin v1.0.4
```

推送 tag 会触发 `Release` 工作流：`scripts/_pack.py` 打包 → 资产**改名为不带版本号的 `dsh-math.tgz`** → 建 draft → 上传 → 最后发布。

### ⚠️ 本仓库开启了「不可变 release」，两条硬约束

1. **已发布的 release 不能再追加或替换资产**。REST 会返回
   `422 Cannot upload assets to an immutable release.` —— 所以资产必须在 draft 阶段补齐，
   工作流也因此改成「先 `gh release create --draft` → `gh release upload` → 再 `--draft=false`」。
2. **tag 名一旦被某个 release 用过就永久占用**，删掉那个 release 也换不回同名 tag
   （会报 `tag_name was used by an immutable release`）。所以补发资产只能用**新 tag 名**，
   不能把旧 release 删掉重建；`v1.0.2`、`v1.0.3` 都已被占用。

> 资产名必须不带版本号：市场用 `.../releases/latest/download/dsh-math.tgz` 这种 URL，
> `latest` 只在请求时解析、文件名照字面取。名字里带版本号的话，提交当天有效、下一次发版就 404。

## 2. 提交 PR

只需要给 awesome-dsh-plugin 仓库加**一个文件**：

```text
data/plugins/SixId666__dsh-math-plugin--plugins-dsh-math.yml
```

内容就是本目录下同名文件（**原样复制，不要改路径前缀**）。步骤：

```powershell
# 1) 在 GitHub 上点 awesome-dsh-plugin/awesome-dsh-plugin 的 Fork
# 2) 克隆自己的 fork
git clone https://github.com/<你的账号>/awesome-dsh-plugin.git
cd awesome-dsh-plugin

# 3) 新建分支
git switch -c add-dsh-math

# 4) 新增那一个文件
#    Windows 下把本目录的 yml 复制到 data\plugins\ 并改名即可
Copy-Item E:\dsh-math\docs\submission\SixId666__dsh-math-plugin--plugins-dsh-math.yml `
          data\plugins\SixId666__dsh-math-plugin--plugins-dsh-math.yml

# 5) 提交并推送
git add data/plugins/SixId666__dsh-math-plugin--plugins-dsh-math.yml
git commit -m "Add SixId666/dsh-math-plugin (dsh-math)"
git push -u origin add-dsh-math
```

然后在 GitHub 上开 PR。PR 正文按仓库的 `PULL_REQUEST_TEMPLATE` 填，说明插件做什么、怎么验证（可引用本仓库的 `tests/` 与 `docs/测试报告.md`）。

⚠️ **不要手工改两个 README**（`README.md` / `README.zh-CN.md` 等由 `data/plugins/*.yml` 生成）；一个 PR 最多 3 条，你只需要 1 条。

## 3. CI 会检查什么（对应 contributing.md 的 “What CI checks”）

1. **条目数** ≤ 3 —— 你只加 1 条。
2. **`dsh.bundle`** —— CI 会从 `url` 指向的目录读 `package.json`，找 `dsh.bundle`。本仓库的 manifest 在 `plugins/dsh-math/package.json`，`url` 也已指向 `.../tree/main/plugins/dsh-math`，位于指南允许的 `plugins/` 子包位置。
3. **仓库年龄 ≥ 1 天** —— 首个 commit 2026-10-03，已满足。
4. **awesome-lint + 站点构建** —— 双语一致性、分隔符、日期、截图（条目里没写 `zh` 也可以，维护者会补；这里已经写了）。

## 4. 评审会看什么（人工）

- 代码是否与描述一致：描述里写了「14 个工具、214 个算子」，`plugins/dsh-math/lib/tools.js` 与 `engine/mathkit/` 必须对得上（当前一致，改功能时记得同步改本条目）。
- 描述里写了「需 Python 3.10+ 及 sympy、mpmath」——这是真实运行前提，属于如实声明，不要删。
- 分类 `tools` 是否贴切（选得不合适由维护者改，不会打回）。
- 是否已被现有条目覆盖（数学/符号计算类目前没有同类条目）。
- 源码有无可疑之处（无网络请求、无安装期脚本、无凭据访问；Python 子进程只跑本仓库自带的 `engine/worker.py`）。

## 5. 常见回退原因与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| CI 说找不到 `dsh.bundle` | `url` 没指向 `plugins/dsh-math` 子目录，或 `package.json` 少了 `dsh.bundle` | 用本目录 yml 里的 `url`；确认 `plugins/dsh-math/package.json` 有 `"dsh": {"bundle": {...}}` |
| CI 说仓库太新 | 仓库创建不足 1 天 | 等一天再提，重新提交没有负面影响 |
| 没人处理 | 维护者还没读 | PR 上评论一句即可，不要重复开 PR（在同一分支推修复） |
| 描述被打回 | 数字/能力与代码不符 | 改 `description.en`（以及 `zh`）即可，不是对插件的否定 |
| Release 工作流报 `422 Cannot upload assets to an immutable release.` | 本仓库开启了不可变 release，已发布的 release 不能再补资产 | 用**新 tag 名**重发；工作流现已改成 draft → upload → publish |
| Release 工作流在 `Normalize the asset name` 失败 | `tar -tzf … \| grep -q` 命中即退出 → tar 收到 SIGPIPE → `pipefail` 判失败 | 已改成 `grep -x … > /dev/null`（`\| head` 同理，别接提前退出的命令） |
| Release 历史里有 3 条红色 run | 上述两个问题在修好之前的三次尝试（`v1.0.2` 移动被 tag 规则拒绝、SIGPIPE、不可变 release） | 已全部修复并写入本文件；`v1.0.3` 的资产是手工用 GitHub API 走 draft 流程补上的 |

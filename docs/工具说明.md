# DSH 考研数学一插件 · 工具注册与调用说明

> 本文档描述插件 `dsh-math` 向 DSH 注册的 14 个数学工具的名称、用途、参数、子操作分派规则、返回结构与典型调用方式。
> 所有工具名、参数名、取值、引擎算子名、返回字段均逐字取自插件源码（`plugin/lib/*.js` 与 `engine/mathkit/*.py`），文末附「文档与代码一致性备注」。

---

## 一、工具总览表

工具命名空间为 `math_*`，插件启动时由 `entry.js` 的 `apply()` 遍历 `TOOL_SPECS` 一次性注册 **14 个工具**。除 §3 列出的通用 `retry` 参数外，每个工具的参数集合与下表一致。

| 工具名 | 用途 | 对应引擎算子（按名列出） | 是否自动验证 |
|---|---|---|---|
| `math_simplify` | 化简与恒等变形：展开、因式分解、通分、部分分式 | `simplify`、`expand`、`factor`、`together`、`apart` | 是。`simplify` 走代回/互印（`independent`/`unverified`）；`expand/factor/together/apart` 走恒等变换取证（`independent`/`cross`/`unverified`） |
| `math_solve` | 解方程与方程组（含参数方程、超越方程） | `solve` | 是（解的代入互印，`independent`/`unverified`） |
| `math_limit` | 极限（双侧/单侧，可含 `oo`） | `limit` | 是（`independent`/`cross`） |
| `math_derivative` | 导数与微分：一元导数、偏导、梯度、雅可比、海塞、方向导数、隐函数、参数方程 | `diff`、`partial`、`gradient`、`jacobian`、`hessian`、`directional_derivative`、`implicit_diff`、`parametric_derivative` | 是。一元导数用 mpmath 独立数值微分（`independent`/`symbolic`/`unverified`），多元算子各自互印 |
| `math_integrate` | 不定积分与定积分（含反常积分） | `integrate` | 是。定积分与独立数值积分交叉比对（`cross`/`unverified`）；不定积分求导代回（`independent`/`unverified`） |
| `math_series` | 泰勒展开与级数求和 | `series`、`sum` | 是。`sum` 为 `independent+numeric`；泰勒展开为阶数-偏差趋势比较（`numeric`/`unverified`） |
| `math_dsolve` | 微分方程求解与解验证 | `dsolve`、`ode_check` | 是（解代回原方程，`independent`/`unverified`） |
| `math_matrix` | 矩阵与线性代数：行列式、逆、秩、转置、乘加、迹、行最简、线性方程组、特征值、对角化、二次型、矩阵幂、总览 | `matrix_analysis`、`det`、`inv`、`rank`、`transpose`、`matmul`、`matadd`、`trace`、`rref`、`solve_linear`、`eigen`、`diagonalize`、`quadratic_form`、`matrix_power` | 是。多路径互印（`independent`/`unverified`），不一致时 note 提示人工复核 |
| `math_probability` | 概率统计：贝叶斯、全概率、条件概率、独立性、容斥、区间/点概率、分布、期望方差协方差相关、联合边缘、矩、自定义分布律、矩估计/极大似然、区间估计、假设检验、抽样分布、中心极限 | `probability`、`distribution`、`expectation`、`variance`、`covariance`、`correlation`、`joint_marginal`、`distribution_moments`、`distribution_from_pmf`、`point_estimate`、`interval_estimate`、`hypothesis_test`、`sampling_distribution`、`central_limit` | 是。基础算子 `independent`/`unverified`；估计与检验类为 `cross`，`central_limit` 为 `independent` |
| `math_numeric` | 高精度数值计算：求值、数值积分、数值求根、数值优化、数值导数、数值极限、数值求和、表达式比对 | `numeric`、`numeric_integrate`、`numeric_solve`、`numeric_optimize`、`numeric_derivative`、`numeric_limit`、`numeric_sum`、`compare_numeric` | 是。全部标记为 `numeric`（数值证据，不构成符号证明） |
| `math_vector_calculus` | 曲线/曲面积分与三大公式（格林、高斯、斯托克斯） | `curve_integral`、`surface_integral`、`green`、`gauss`、`stokes` | 是。曲线/曲面积分为 `symbolic+numeric`，三大公式为 `independent`，退化情形 `unverified` |
| `math_verify` | 独立验证机制：对任意已有结果做机制不同的复核 | `verify`（内部按 `kind` 分派到 `_HANDLERS` 中的独立实现：`derivative`/`integral`/`limit`/`equation_solution`/`identity`/`matrix_inverse`/`determinant`/`eigen`/`probability`/`expectation`/`variance`/`normalization`/`general` 等） | 是（本工具即验证器；输出 `verification.status` = `independent`/`cross`/`numeric`/`unverified`） |
| `math_analysis` | 函数分析：完整分析、定义域、渐近线、多元极值、拉格朗日乘数、多元泰勒、不等式、中值定理点 | `function_analysis`、`domain`、`asymptote`、`multivar_extremum`、`lagrange`、`taylor_multivar`、`inequality`、`mean_value_point` | 是。各算子用必要条件的残差复核或数值抽样（`verified`/`partially_verified`/`unverified`） |
| `math_status` | 引擎运行状态：算子清单、缓存统计、缓存清空（诊断用） | 控制操作 `@cache_stats` / `@ops` / `@cache_clear`（另有未暴露的 `@ping`） | 否（诊断工具，不产生数学结果） |

**说明两点事实：**

1. 引擎里还存在未通过工具暴露的算子：`integrate_multi`（重积分，`calculus.py:1199`）、`numeric_matrix`（`numeric.py:2941`）、`moment_generating`（`probability.py:2926`）、`implicit_function_extremum`（`symbolic_extra.py:2903`）、`conditional_check`/`domain_check`（`verifier.py:2415`/`2622`）。它们只能用名字直接打引擎，工具表不提供入口。
2. `gradient`/`jacobian`/`hessian` 在 `calculus.py` 与 `symbolic_extra.py` 各注册一次，后导入的 `symbolic_extra` 版本生效（`ops.py` 的 `_HANDLER_MODULES` 顺序决定）。

## 二、每个工具的详细说明

### 通用约定（适用于全部 14 个工具）

- **隐式追加的 `retry` 参数**：`entry.js:96-138` 的 `buildTool()` 给每个工具额外加了一个布尔参数 `retry`，描述为「是否允许对完全相同的参数再尝试一次（默认不允许）。只有在确有理由（例如引擎刚才崩过、外部条件变了）时才用；改参数或换方法不需要这个开关。」下文的参数表不再重复列出它。
- **参数类型方言**：`tools.js` 用两个内部简写生成 schema——`S(desc, required=true)` 生成 `{type:"string"}`，`A(desc, required=false)` 生成 `{type:"array", items:{type:"string"}}`，`N(desc)` 生成 `{type:"number"}`。`define_tool.js:81-96` 的 `compilePropertyMap()` 只把 `required === true` 的属性写进 JSON Schema 的 `required` 数组（DSH 作者级 schema 中 `required:false` 是非法的）。
- **参数名校验**：`define_tool.js:121-175` 的 `validateArguments()` 先校验再执行，未知参数与类型不符都会以 `ToolArgsError` 拒绝，渲染成「参数校验失败：invalid arguments: …」（`render.js` 的 `renderArgError`）。
- **值别名归一化**：即便模型写错参数名，`engine.py:29-86` 的 `ARG_ALIASES` 仍会兜底（`expression/e/f/input/formula/func→expr`；`variable/wrt/x→var`；`point/at/x0→point`；`dir/direction/side→dir`；`lo→lower`、`hi→upper`、`a→lower`、`b→upper`；`n/order/times/degree/terms→order`；`eqs/system/equation→equations`；`A/M/mat/matrix1/matrix_a→matrix`；`B/matrix2→matrix_b`；`answer/result_expr→candidate`；`type/op_type/claim_type→kind`；`samples→trials`）。**这只减少失败，不应被当作正式用法——请按本文档的参数名写。**
- **无匹配的静默裁剪**：`engine.py:170-196` 的 `_call_with_declared_kwargs()` 按算子函数签名裁剪多余参数。传了一个算子签名里没有的参数不会报错，而是被静默丢弃——这也是下文中少数「参数无效」现象的根源。

### 1. `math_simplify` — 化简与恒等变形

- **用途**（`title`/`short`）：化简与恒等变形；化简表达式、展开、因式分解、通分、部分分式。
- **默认引擎算子**：`simplify`。

**参数表**

| 参数名 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `expr` | string | 是 | 待处理的数学表达式。支持 LaTeX 与自然写法，例如 `1/(x^2-1)`、`\frac{x^2-1}{x-1}`、`sin(x)^2+cos(x)^2`。 |
| `mode` | string | 否 | 变形方式：`simplify`（默认）\| `expand` \| `factor` \| `together` \| `apart`。 |
| `var` | string | 否 | 部分分式分解（`mode=apart`）的分解变量，例如 `x`。留空时由 SymPy 自行选择。 |

**子操作分派表**（`tools.js:75-99` 的 `args` 函数）

| `mode` 取值 | 引擎算子 | 实际传参 | 备注 |
|---|---|---|---|
| `simplify`（默认） | `simplify` | `{expr}` | |
| `expand` | `expand` | `{expr}` | 走 `mode` 本身作为算子名 |
| `factor` | `factor` | `{expr}` | 同上 |
| `together` | `together` | `{expr}` | **不传 `var`**：`sp.together` 的第二个位置参数是 `deep` 而不是变量，传 `var` 会被引擎静默丢弃，所以源码刻意不带 |
| `apart` | `apart` | `{expr, var}` | 五个分支里唯一带 `var` 的 |

**何时不该调用**（`description` 尾部的 `MSG_WHEN_NOT`）：不需要调用的情况：可以口算或直接套用基础公式的简单算式；题目考查的是证明思路、定理适用条件或解题策略而不是具体计算；几何关系、积分区域、法向量方向这类必须靠数学分析判断的问题。

---

### 2. `math_solve` — 解方程与方程组

- **用途**：解方程与方程组（含参数方程、超越方程）。
- **默认引擎算子**：`solve`。

**参数表**

| 参数名 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `equations` | array\<string\> | 是 | 一个或多个方程。可含等号，例如 `['x^2-3*x+2=0']` 或 `['x+y=3','x-y=1']`；也可写成不含等号的表达式，此时默认等于 0。 |
| `vars` | array\<string\> | 否 | 未知数列表，例如 `['x', 'y']`。留空时自动识别。 |

**子操作分派表**

本工具无 `mode`/`kind` 分派，恒为 `{op:"solve", args:{equations, vars}}`。方程组通过 `equations` 数组长度表达。

**何时不该调用**：同 `MSG_WHEN_NOT`（口算可得、考查证明思路、需数学分析判断的题）。此外，若只需确认某个解是否正确，应改用 `math_verify`（`kind:"equation_solution"`）而不是再解一次。

---

### 3. `math_limit` — 极限

- **用途**：求极限（双侧或单侧，可含 `oo`）。
- **默认引擎算子**：`limit`。

**参数表**

| 参数名 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `expr` | string | 是 | 函数表达式，例如 `sin(x)/x`、`(1+1/n)^n`、`x*log(x)`。 |
| `var` | string | 否 | 自变量，例如 `x` 或 `n`。留空时自动识别唯一自由变量。 |
| `point` | string | 否 | 趋近点，例如 `0`、`1`、`oo`、`-oo`、`无穷`。 |
| `dir` | string | 否 | 趋近方向：`+`（右极限）、`-`（左极限），留空为双侧。 |

**子操作分派表**

无分派，恒为 `{op:"limit", args:{expr, var, point, dir}}`。**注意 `point` 有硬编码默认值**：`args` 里写的是 `point: a.point ?? "0"`，即不传 `point` 时按「趋于 0」计算而不是自动猜测。引擎侧 `dir` 还有值别名：`+`/`right`/`大于`/`above`/`gt` → `+`，`-`/`left`/`小于`/`below`/`lt` → `-`（`engine.py` 的 `VALUE_ALIASES`）。

**何时不该调用**：同 `MSG_WHEN_NOT`；仅需数值估计时可用 `math_numeric` 的 `mode:"limit"`，但那只给数值证据。

---

### 4. `math_derivative` — 导数与微分

- **用途**：导数与微分；一元导数、偏导、梯度、雅可比矩阵、海塞矩阵、方向导数、隐函数求导、参数方程求导。
- **默认引擎算子**：`diff`（`mode=derivative`）。

**参数表**

| 参数名 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `expr` | string | 是 | 函数表达式，例如 `x^x`、`ln(x+sqrt(1+x^2))`、`x^2*y+y^3`。 |
| `var` | string | 否 | 求导变量，例如 `x`。留空时自动识别。 |
| `order` | number | 否 | 阶数，默认 1。例如 2 表示二阶导。 |
| `variables` | array\<string\> | 否 | 多元情形下的变量列表，如 `['x','y']`（用于 gradient / jacobian / hessian / directional_derivative）。 |
| `mode` | string | 否 | 求导类型：`derivative`（默认，一元导数）\| `partial`（偏导）\| `gradient` \| `jacobian` \| `hessian` \| `directional` \| `implicit` \| `parametric`。 |
| `point` | array\<string\> | 否 | 求值点或方向向量（directional 模式的方向），如 `['1','1']`。 |
| `direction` | array\<string\> | 否 | 方向导数的方向向量，如 `['1','1']`。 |
| `equation` | string | 否 | implicit 模式的隐式方程，如 `x^2+y^2=1`。（仅 mode=implicit 需要） |
| `x_expr` | string | 否 | parametric 模式的 x(t)，如 `cos(t)`。（仅 mode=parametric 需要） |
| `y_expr` | string | 否 | parametric 模式的 y(t)，如 `sin(t)`。（仅 mode=parametric 需要） |
| `param` | string | 否 | parametric 模式的参数名，默认 `t`。 |

**子操作分派表**（`tools.js:139-183`）

| `mode` 取值 | 引擎算子 | 实际传参 | 关键映射逻辑 |
|---|---|---|---|
| `derivative`（默认，含未识别取值） | `diff` | `{expr, var, order: a.order ?? 1}` | `order` 缺省补 1 |
| `partial` | `partial` | `{expr, var, order: a.order ?? 1}` | 偏导复用一元 `var`（不是 `variables`） |
| `gradient` | `gradient` | `{expr, vars: a.variables}` | 变量来源是 `variables` 数组 |
| `jacobian` | `jacobian` | `{exprs: a.expr, vars: a.variables}` | **参数名变了**：`expr` → 引擎的 `exprs` |
| `hessian` | `hessian` | `{expr, vars: a.variables}` | |
| `directional` | `directional_derivative` | `{expr, vars: a.variables, point: a.point, direction: a.direction ?? a.point}` | 方向缺省时**回落到 `point`** |
| `implicit` | `implicit_diff` | `{equation, vars: a.variables, order: a.order ?? 1}` | 隐函数方程走 `equation`，不需要 `expr` |
| `parametric` | `parametric_derivative` | `{x_expr, y_expr, param: a.param ?? "t", order: a.order ?? 1}` | `param` 缺省补 `t` |

**何时不该调用**：同 `MSG_WHEN_NOT`；单纯把 `x=2` 代入求值属于代入计算，用 `math_simplify`/`math_numeric` 更贴切。

### 5. `math_integrate` — 积分

- **用途**：求不定积分与定积分（含反常积分）。
- **默认引擎算子**：`integrate`；**无子操作分派**。

**参数表**

| 参数名 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `expr` | string | 是 | 被积函数，例如 `x*exp(x^2)`、`1/(1+x^2)`、`sin(x)/x`。 |
| `var` | string | 否 | 积分变量，默认 `x`。 |
| `lower` | string | 否 | 积分下限，例如 `0`、`-oo`、`无穷`。留空表示不定积分。 |
| `upper` | string | 否 | 积分上限，例如 `1`、`oo`、`无穷`。 |

**子操作分派表**

无分派，恒为 `{op:"integrate", args:{expr, var, lower, upper}}`。定/不定、常义/反常积分全部由 `lower`/`upper` 是否给出决定，引擎内部再区分到「定积分」「不定积分」两条实现路径。**`description` 中有一条硬性纪律**：「重要：像 ∫₀¹x²dx 这样的积分也应直接调用本工具取得精确结果，不要为了它去写 Python 程序、建临时文件再执行——那就是被明确禁止的无必要程序编写。」

**何时不该调用**：同 `MSG_WHEN_NOT`；需要重积分时本工具不提供入口（引擎有 `integrate_multi` 算子但未注册成工具）。

### 6. `math_series` — 级数与泰勒展开

- **用途**：级数与泰勒展开（含麦克劳林展开、级数求和）。
- **默认引擎算子**：`series`（`mode=taylor`）。

**参数表**

| 参数名 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `expr` | string | 是 | 函数或被求和的通项，例如 `sin(x)`、`1/n^2`、`x^n/n`。 |
| `var` | string | 否 | 变量或求和指标，例如 `x`、`n`。 |
| `point` | string | 否 | 展开点（仅 mode=taylor 使用），例如 `0` 表示麦克劳林展开。 |
| `order` | number | 否 | 展开阶数或求和阶数，默认 6。 |
| `mode` | string | 否 | `taylor`（默认，泰勒展开）\| `sum`（级数求和）。 |
| `lower` | string | 否 | 求和下限（mode=sum），默认 `1`。 |
| `upper` | string | 否 | 求和上限（mode=sum），默认 `oo`。 |

**子操作分派表**

| `mode` 取值 | 引擎算子 | 实际传参 | 关键映射逻辑 |
|---|---|---|---|
| `sum` | `sum` | `{expr, var, lower: a.lower ?? "1", upper: a.upper ?? "oo"}` | `lower` 缺省 `1`、`upper` 缺省 `oo`（无穷级数默认值）；`point`/`order` 在该分支被丢弃 |
| 其他（含默认 `taylor`） | `series` | `{expr, var, point: a.point ?? "0", order: a.order ?? 6}` | `point` 缺省 `0`（麦克劳林）、`order` 缺省 `6`；`lower`/`upper` 在该分支被丢弃 |

**何时不该调用**：同 `MSG_WHEN_NOT`。`description` 另有一条重要提示：「泰勒展开是局部近似而不是恒等式，工具会在返回里注明这一点」——所以不要把展开式当恒等式使用；求收敛半径/和函数属于级数求和，用 `mode:"sum"`。

### 7. `math_dsolve` — 微分方程

- **用途**：微分方程求解与解验证。
- **默认引擎算子**：`dsolve`。

**参数表**

| 参数名 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `equations` | array\<string\> | 是 | 一个或多个微分方程，例如 `["y' - 2*y = 0"]`、`['diff(y(x),x,2)+y=0']`。含初值条件时一同给出。 |
| `vars` | array\<string\> | 否 | 自变量列表，默认 `['x']`。 |
| `funcs` | array\<string\> | 否 | 未知函数列表，例如 `['y']`。 |
| `candidate` | string | 否 | `mode=check` 时待验证的解表达式。 |
| `mode` | string | 否 | `solve`（默认，求解）\| `check`（验证给定的解）。 |

**子操作分派表**

| `mode` 取值 | 引擎算子 | 实际传参 |
|---|---|---|
| `check` | `ode_check` | `{equations, candidate, vars, funcs}` |
| 其他（含默认 `solve`） | `dsolve` | `{equations, vars, funcs}` |

导数写法 `'y\''` 或 `'diff(y(x),x)'` 都可以（`description` 原文）。初值条件与方程一起放进 `equations` 数组。

**何时不该调用**：同 `MSG_WHEN_NOT`；若只是验证「某个函数是不是解」，用 `mode:"check"` 或 `math_verify`（`kind:"equation_solution"`），不要重新解一遍。

### 8. `math_matrix` — 矩阵与线性代数

**子操作分派表**（`tools.js:263-299`）

前置处理：`op = (a.operation ?? "analysis").toLowerCase()`；`matrix = matrixArg(a.matrix)`；`matrixB = matrixArg(a.matrix_b)`；`rhs = matrixArg(a.rhs ?? a.matrix_b)`。

其中 `matrixArg`（`tools.js:62-67`）的规则是：`undefined`/`null`/字符串原样返回；二维行数组原样返回；否则执行 `value.map(row => String(row)).join(";")`。因此 `['1,2','3,4']` 会被拼成 `"1,2;3,4"`。**注意：引擎把一维字符串数组当单行处理，`['1,2','3,4']` 若不经这层拼接会报「非方阵」。**

**参数校验层同时接受两种写法**：`matrix`/`matrix_b`（本工具与 `math_verify` 的同类参数共 4 处）在 **1.0.2 起**用 `oneOf` 声明为「字符串数组 **或** 单个字符串」（`tools.js` 的 `AS` 助手）；1.0.1 及以前只声明数组，于是照本表写 `'1,2;3,4'` 会在校验处被拒，报 `invalid arguments: arguments.matrix must be a array (got string)`——这与参数描述自相矛盾，已修复。非法形态（数字、数组里混入数字）仍会被拒，报 `arguments.matrix must match one of the allowed schemas`。

| `operation` 取值 | 引擎算子 | 实际传参 |
|---|---|---|
| `power` | `matrix_power` | `{matrix, order: a.order ?? 2}`（幂指数缺省 2） |
| `quadratic` | `quadratic_form` | `{expr: a.expr, matrix, variables: a.variables}` | **1.0.2 修复**：1.0.1 及以前误写为 `vars: a.vars`（未声明，恒为 `undefined`） |
| `solve_linear` | `solve_linear` | `{matrix, rhs}` |
| `transpose` | `transpose` | `{matrix}` |
| `matmul` | `matmul` | `{matrix, matrix_b: matrixB}` |
| `matadd` | `matadd` | `{matrix, matrix_b: matrixB}` |
| `analysis` / `det` / `inv` / `rank` / `trace` / `rref` / `eigen` / `diagonalize`（含任意未识别取值） | 与取值同名的算子 | `{matrix}`（`op` 本身作为算子名下发） |

两条容易踩坑的映射事实：

- `solve_linear` 的右端项优先取 `rhs`，**其次回落到 `matrix_b`**（`matrixArg(a.rhs ?? a.matrix_b)`）；`quadratic` 传的是 `variables: a.variables`（**1.0.2 修复**：1.0.1 及以前写的是 `vars: a.vars`，而 `params` 里只有 `variables`，于是该字段恒为 `undefined`，二次型变量名只能由引擎自行解析 `x1`/`x2`；现在可显式指定，留空时仍由引擎自动识别，例如 `{operation:"quadratic", expr:"x1^2+2*x1*x2+3*x2^2"}` → 「正定」，`symbol_extraction: 二次型变量 = ['x1', 'x2']`）。
- 除上表显式列出的分支外，任何拼写错误的 `operation` 都会原样当作引擎算子名下发，最终由 `engine.py` 报 `unknown_operation`（`未知操作 …；可用操作：…`），不会被 JS 侧提前拦截。

**何时不该调用**：同 `MSG_WHEN_NOT`；矩阵规模很小时手算更快；证明「矩阵可对角化」的充分/必要条件属于理论题，工具只给计算结果。

| `expr` | string | 否 | 原始表达式 / 被积函数 / 原方程，视 kind 而定。例如 kind=derivative 时填 `x^2`。矩阵类验证（matrix_inverse/determinant/eigen）不需要 expr，给出 matrix 即可。 |
| `candidate` | string | **是** | 待验证的结果，例如 `2*x`（矩阵类验证时填数值或矩阵）。 |
| `kind` | string | 否 | 验证类型：`general`（默认）\| `derivative` \| `integral`（不定积分）\| `definite_integral` \| `limit` \| `equation_solution` \| `identity` \| `simplify` \| `factor` \| `expand` \| `matrix_inverse` \| `determinant` \| `eigen` \| `probability` \| `expectation` \| `variance` \| `normalization`。 |
| `var` | string | 否 | 变量，例如 `x`。 |
| `vars` | array\<string\> | 否 | 变量列表。 |
| `equations` | array\<string\> | 否 | 原方程（kind=equation_solution 或方程组时使用）。 |
| `point` | string | 否 | 求值点或极限点。 |
| `lower` | string | 否 | 定积分下限。 |
| `upper` | string | 否 | 定积分上限。 |
| `matrix` | array\<string\> \| string | 否 | 原矩阵（矩阵类验证），例如 `['1,2','3,4']` 或 `'1,2;3,4'`。 |
| `matrix_b` | array\<string\> \| string | 否 | 第二个矩阵，例如 `['1,0','0,1']` 或 `'1,0;0,1'`。 |
| `conditions` | string | 否 | 用户声明的附加条件与定义域，例如 `x>0`。工具会说明这些条件是否真正被纳入验证。 |

**子操作分派表**

本工具不做 JS 侧分派，恒为 `{op:"verify", args:{...a, matrix:matrixArg(a.matrix), matrix_b:matrixArg(a.matrix_b)}}`——即把全部参数原样透传，只对 `matrix`/`matrix_b` 做「粘成 `"1,2;3,4"`」的预处理。真正的分派发生在 `verifier.py`：

| 层面 | 事实 |
|---|---|
| `kind` → 验证实现 | `verifier.py` 的 `_HANDLERS` 表（`verifier.py:2117-2140`）覆盖 `derivative`/`integral`/`antiderivative`/`indefinite_integral`/`definite_integral`/`limit`/`equation_solution`/`solution`/`identity`/`simplify`/`factor`/`expand`/`matrix_inverse`/`inverse_matrix`/`determinant`/`eigen`/`eigenvalue`/`probability`/`expectation`/`variance`/`normalization`/`general` |
| 中文别名 | `_KIND_ALIASES`（`verifier.py:2143-2154`）接受：导数/积分/定积分/极限/解方程/恒等式/化简/因式分解/展开/逆矩阵/行列式/特征值/概率/期望/均值/方差/归一化 |
| 必需参数缺失 | 缺 `candidate` 抛 `缺少必需参数 candidate（待验证的结果，别名 result_expr / answer）`；矩阵类缺 `matrix` 抛 `该计算类型需要 matrix 参数（矩阵 A）`；`derivative`/`integral` 等缺 `expr` 抛 `该计算类型需要 expr（原始表达式 / 被积函数）` |
| 证据不足 | `LEVEL_NONE` 或 `passed is None` → 返回 `MathResult.unsolved("verify", …)`，措辞为具体原因或「证据不足，无法完成独立复核」 |
| 条件追踪 | 未被验证用到的条件经 `_unhandled_from`（`verifier.py:2101`）写入 `unhandled_conditions`（三类措辞）；`numeric` 级追加条件「本次复核只获得数值证据（抽样/数值积分/精确分布函数求值），不是符号级证明…」；`symbolic` 级追加「本次复核获得符号级证据…」 |
| 未通过 | `passed === False` 时追加 warning「复核未通过：…」 |

**何时不该调用**：同 `MSG_WHEN_NOT`。也不要把它当「再算一遍」用——它的价值在于机制不同（数值抽样、代回残差、多路径互印），重复同一算法得不到新信息。

| `mode` 取值 | 引擎算子 | 实际传参 | 关键映射逻辑 |

### 14. `math_status` — 数学引擎状态

- **用途**（`description` 原文）：查看数学计算引擎的运行状态：可用算子清单、缓存命中率、已记录的成功与失败计算。用于诊断「为什么某个计算没有执行」或确认缓存是否生效。日常解题不需要调用。
- **控制工具**：`control: true`，不进缓存。

**参数表**

| 参数名 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `action` | string | 否 | `status`（默认）\| `ops`（算子清单）\| `cache_stats` \| `cache_clear`。 |

**子操作分派表**（`tools.js:650-662`）

`args` 是一个**返回对象而非纯对象**的函数：`({op:"@cache_stats", args:{}, control:(a.action ?? "status").toLowerCase()})`。也就是说引擎侧的 op 恒为 `@cache_stats`，真正区分行为的是 `control` 字段：

| `action` 取值 | `control` 值 | 实际行为（`entry.js:253-300`） |
|---|---|---|
| `status`（默认） | `status` | 打印 Python 命令与其来源、`workerPath`、Node 侧命中/未命中/命中率/被拦截的重复失败重试次数、Python 侧 `success_entries`/`failure_entries`/`hits`，以及最近 3 条日志 |
| `ops` | `ops` | 调 `control("@ops")`，输出引擎可用算子总数与算子清单 |
| `cache_stats` | `cache_stats` | 输出 Python 侧缓存统计（`success_entries`/`failure_entries`/`hits`/`misses`/`hit_rate`） |
| `cache_clear` | `cache_clear` | 调 `control("@cache_clear")` 并清空 Node 侧 `MathLedger` |

注意 `status` 分支由 `entry.js` 的 `MathEngine.execute()` 直通 `status()`，**不会**走 `@cache_stats` 请求；其余三个 action 才真正下发控制操作。

**何时不该调用**：日常解题完全不调用（`description` 明说）；不要用 `cache_clear` 来「重试一个失败的计算」，那属于 `retry` 参数的职责，且会一并清掉有效缓存。

## 三、统一返回结构

### 3.1 JS → Python 的请求协议

`bridge.js` 与 `worker.py` 之间是**逐行 JSON（newline-delimited JSON）**协议，一次请求一个对象：

| 字段 | 来源 | 说明 |
|---|---|---|
| `id` | bridge 自增 | 配对请求与响应 |
| `op` | 工具的 `op`（如 `integrate`）或控制操作（`@ops`/`@cache_stats`/`@cache_clear`/`@ping`/`@shutdown`） | 引擎算子名 |
| `args` | 工具的 `args` 函数产物 | 算子实参（已按上文各分派表映射） |
| `timeout` | `timeoutMs / 1000`（秒） | 默认 60 秒（`entry.js` 的 `DEFAULT_TIMEOUT_MS`），引擎侧另有 30 秒兜底 |
| `cache` | 插件配置 `cache`（默认 `true`） | 是否允许引擎侧缓存 |

响应为 `{"id":…, "ok":true|false, "data":{…}}`；`data` 就是引擎 `MathResult.to_dict()` 的结果。bridge 取值用 `message.data ?? message`，所以工具最终拿到的是 `data` 本体。

### 3.2 引擎返回字段（`result.py` 的 `to_dict()`，`engine.py` 的 `execute()` 保证字段完整）

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | boolean | **等于 `status == "ok"` 的派生字段**，不是独立语义 |
| `status` | string | `ok` \| `partial` \| `unsolved` \| `error`（见 3.3） |
| `operation` | string | 实际执行的引擎算子名 |
| `method` | string | 本次采用的方法描述 |
| `input` | object | 归一化后的输入（可用于确认「引擎到底收到了什么」） |
| `result` | object | 结果主体；数值经 `_unwrap` 变成 `{text, latex, approx}` 三元组，`approx` 由 `sp.N(value,17)` 给出 |
| `conditions` | array\<string\> | 成立条件、定义域限制、反常积分收敛性等前提 |
| `verification` | object | `{status, methods:[…], passed?, level?, method?, evidence?, unhandled_conditions?, cannot_verify_reason?, conditions_used?, note?}` |
| `error` | object | **仅非 `None` 时出现**：`{kind, message}` |
| `warnings` | array\<string\> | 需要模型注意的提醒（如「复核未通过」「发散的反常积分」） |
| `extra` | object | **仅非空时出现**：算子特有的附加信息（如 `verification_detail`、`methods_tried`、`hint`/`suggestion`） |
| `elapsed_ms` | number | 耗时。**所有返回路径都会写**，包括超时与异常 |

### 3.3 `status` 取值语义

| 取值 | 语义 | 触发场景 |
|---|---|---|
| `ok` | 成功求得结果 | 算子正常返回。**只有 `ok` 才会被写入缓存**（Node 侧 `MathLedger` 与 Python 侧 worker 缓存均如此） |
| `partial` | 部分成功：主结果可用但有已知缺口 | 例如「导数结果未通过独立复核」「驻点方程组无解、极值只能在边界取得」 |
| `unsolved` | **当前方法求不出解析结果** | 例如 `verify` 证据不足、「SymPy 无法解析求解该方程组」。**这不是报错**，而是诚实的「没求出来」 |
| `error` | 执行失败 | `unknown_operation`、`invalid_input`、`timeout`、`recursion`、`memory`、`internal`、`engine_unavailable`、`repeated_failure`、`protocol` |

### 3.4 `verification.status` 取值语义

`verification.status` 由各算子按证据强度自行填写，源码中实际出现的取值有：

| 取值 | 语义 |
|---|---|
| `independent` | **独立机制核验通过**：用与主算法不同的路径（数值微分、代回残差、多路径互印、独立求解）得到一致结果 |
| `independent+numeric` | 同时具备独立机制与数值证据（`calculus.py` 的级数求和算子使用） |
| `symbolic+numeric` | 既有符号级证据又有数值证据（`vector_calc.py` 的曲线/曲面积分与部分斯托克斯分支使用） |
| `cross` | **交叉验证通过**：与另一条路线交叉比对一致（如符号积分 vs 独立数值积分；`probability_extra.py` 的估计/检验类） |
| `symbolic` | 符号级核验通过，但缺独立数值证据（一元导数在数值微分未取到有效证据时降级到此状态） |
| `numeric` | **仅数值抽样一致——数值证据，不构成符号证明**（`numeric.py` 全族、泰勒展开的阶数-偏差趋势比较） |
| `verified` | 该算子自定义的「已验证」（`symbolic_extra.py` 的域/极值/不等式/中值定理等分支） |
| `partially_verified` | 部分验证通过：部分候选点/部分条件通过（`symbolic_extra.py` 多处） |
| `unverified` | **未能验证 / 未验证**：证据不足或证据不一致 |
| `none` | 常量 `LEVEL_NONE`，表示「没有可用验证路径」（`verifier.py` 内部层级，最终会转化为 `unverified` 或 `unsolved`） |

`verification` 还可携带 `passed`（布尔）、`level`（`symbolic`/`numeric`/`none`）、`method`、`evidence`、`unhandled_conditions`、`cannot_verify_reason`、`conditions_used`、`note`。

### 3.5 「未求得绝不冒充成功」的设计

这条原则落实在四处，读代码即可逐条核验：

1. **`success` 只是 `status == "ok"` 的派生量**（`result.py` 的 `to_dict()`），不存在「有结果就算成功」的旁路。
2. **缓存的准入条件就是 `status == "ok"`**（Node 侧 `MathLedger` 只把 `ok` 记为 success，Python 侧 worker 同样只在 `status == "ok"` 时写入缓存）。因此「未求得」的结果**不会**被缓存成成功答案。
3. **失败会被记账并拦截重复**：同参数失败进入 `failures`，在 `allowRetry` 为假（默认）时，下一次相同参数的请求被直接截断为 `status:"error"`、`error.kind:"repeated_failure"`，并附 warning「这一组完全相同的参数此前已经失败过，按防止重复计算的原则不再重复尝试…」。这是防止模型陷入「反复重试同一失败计算」的护栏。
4. **验证状态与措辞分离**：`render.js` 的 `VERIFY_LABEL` 提供「通过」措辞、`VERIFY_LABEL_FAIL` 提供「未通过」措辞，`passed === false` 时必须换用后者；`numeric` 级证据的固定措辞是「仅数值抽样一致（数值证据，不构成符号证明）」。渲染层不会把数值一致渲染成「已证明」。

## 五、四类任务模式

插件通过 systemPrompt section `dsh-math:tools`（`entry.js:68-94`，顺序 2500）向模型下达 7 条纪律；四类任务模式**不需要用户手动指定**，由模型按自然语言自行识别，工具在其中承担的角色不同。下面按模式说明「模型该做什么、工具该做什么」。

### A. 计算模式

- **识别特征**：题目要求「求/算/化简/展开/解出」一个确定结果。
- **模型角色**：把自然语言题目翻译成工具参数（表达式、变量、上下限、矩阵、分布参数），拿到结果后负责解释与呈现。
- **工具角色**：承担全部符号/数值计算。对应纪律「计算交给工具」与「不要为简单计算自写程序」——**像 ∫₀¹x²dx 这样的积分也必须直接调 `math_integrate`，不要写 Python 程序或建临时文件再执行**（`math_integrate` 的 `description` 原文点名了这种被禁止的做法）。
- **终止条件**：纪律「已获得可靠结果就停止」——`status:"ok"` 且验证状态为 `independent`/`cross` 等通过项时，不要为了「再确认一下」重复调用同一工具。

### B. 验证模式

- **识别特征**：题目或用户要求「验证/检验/判断某个结果是否正确」，或模型自己需要确认上一轮结果。
- **模型角色**：给出**原始对象 + 待验证结果**这一对（`expr`/`equations`/`matrix` 与 `candidate`），并读懂验证证据。
- **工具角色**：`math_verify` 用与主算法**机制不同**的路径复核（数值抽样、代回残差、多路径互印），引擎内各算子也自带验证。对应纪律「验证交给独立机制」。
- **必须能定位具体错误，而不是只判对错**：返回的 `verification.methods` 逐条给出方法与结论，`passed === false` 时渲染层会打出「验证: 未通过 — …」并附 `关键证据:`（由 `summarizeEvidence` 抽取 `difference`/`counterexample`/`expected`/`derivative_of_candidate`/`closed_form`/`residuals`/`numeric`/`finite_difference`/`check_*_agree` 等字段，单值截断 180 字符），未通过还会追加 warning「复核未通过：…」。因此模型应当引用**具体哪条途径、差多少、哪个条件没被纳入**，而不是只说「不通过」。
- **条件必须显式交代**：`verification.unhandled_conditions` 列出「声明了但没被真正纳入验证」的条件，`cannot_verify_reason` 说明为什么无法验证——这两项必须如实转述，不能省略。

### C. 思路分析模式

- **识别特征**：用户问「这题怎么做/用什么方法/为什么这样想」，不要求具体数值结果。
- **模型角色**：主导。对应纪律「不要跳过数学推理与讲解」。
- **工具角色**：**最小化**。`MSG_WHEN_NOT` 明确说：「题目考查的是证明思路、定理适用条件或解题策略而不是具体计算」「几何关系、积分区域、法向量方向这类必须靠数学分析判断的问题」——这些情况下**不调用工具**。工具只用于顺便算一个中间量（例如用 `math_analysis` 的 `mode:"domain"` 确认定义域，用 `math_derivative` 的 `mode:"gradient"` 得到梯度表达式以说明几何意义）。
- **风险提示**：本模式最容易出现「为了算一个口算量而调工具」和「用工具输出替代推理」两种偏差，两者都被纪律明确禁止。

### D. 完整解题模式

- **识别特征**：用户要求「完整解答这道题」「按考试步骤写」。
- **模型角色**：组织完整的阅卷式解答。
- **工具角色**：为第 5、6 两项提供可信输入（具体计算与结果验证），其余各项由模型撰写。
- **八项内容（顺序固定）**：
  1. **题目分析**——已知条件、所求目标、隐含约束；
  2. **考点识别**——本题属于哪一章、考查哪个定理/方法（对应纪律「如实报告」中对考点交代的要求）；
  3. **解题思路**——为什么选这条路，其它路为何不走；
  4. **关键公式**——写出用到的公式及其适用条件；
  5. **具体计算**——由工具给出（`math_*` 系列），模型只负责转写与解释，不得自行推算或编造中间步骤；
  6. **计算结果验证**——由 `math_verify` 或算子自带验证给出，转述时保留验证状态与证据；若状态是 `numeric`，必须说明「这是数值证据，不是符号证明」；
  7. **最终答案**——明确结论，含定义域/成立条件；
  8. **同类识别技巧**——这类题的特征、易错点、判别要点。
- **纪律约束**：若第 5 项返回 `unsolved`，必须如实说明「当前方法求不出解析解」并给出替代路径（例如改用 `math_numeric`），**不得**把 `unsolved` 包装成答案；若返回 `error`，如实说明是执行失败并给出 `error.kind`/`message`（对应纪律「如实报告」）。追问某一步时只回答该步，不要重写整篇。

**发现的源码与直觉不一致之处（均以源码为准记录）：**

1. **`math_matrix` 的 `quadratic` 分支曾引用未声明的参数**：`args` 里原写 `vars: a.vars`，但 `params` 中并没有 `vars` 字段（只有 `variables`）。因此二次型分支的 `vars` 恒为 `undefined`，变量名由引擎自行解析 `x1`/`x2`。**已修复（1.0.2）**：改为 `variables: a.variables` 并补上 `variables` 参数声明。
2. **`math_limit` 的 `point` 有硬编码默认 `"0"`**（`point: a.point ?? "0"`），而不是「留空时自动判断趋近点」。文档中必须按此说明，否则用户会以为不传 `point` 可以自动识别。
3. **`math_analysis` 的 `taylor` 默认阶数为 2**（`order: a.order ?? 2`），与 `math_series` 的默认 6 不同；两个工具都叫「泰勒展开」但默认行为不一致。
4. **`math_numeric` 的 `eval` 分支把 `values` 传给引擎的 `vars` 形参**（`{op:"numeric", args:{expr, vars: values, digits}}`），`solve` 分支把 `values` 传给 `guesses`、把 `expr` 改名为 `equations`——参数名转换幅度较大，容易误用。
5. **`math_probability` 的 `distribution`/`pdf`/`cdf`/`pmf` 四个取值曾读 `mode` 字段**（`kind: p.mode ?? kind`），而 `mode` 并未在 `params` 中声明。**已修复（1.0.2）**：改为直接 `{...p, kind}`，不再有未文档化的隐式入口。
6. **`math_vector_calculus` 的 `r` 参数是刻意命名**：源码注释说明「避开 `r_component` 是因为它与参数名 `r_component` 重名」，JS 侧再把它映射回引擎的 `r_component`。
7. **`render.js` 的 `VERIFY_LABEL` 曾未覆盖全部真实状态串**：`symbolic+numeric`、`independent+numeric`、`verified`、`partially_verified` 原先在标签表里没有条目，会原样显示英文/加号串。**已修复（1.0.2）**：四者都已加入 `VERIFY_LABEL`，`VERIFY_LABEL_FAIL` 也同步补齐（否则 `passed===false` 时会原样回显 level 字符串）。阅读返回时仍请按 §3.4 的语义表理解这些取值。
8. **`math_simplify` 的 `together` 分支刻意不传 `var`**：源码注释（`tools.js:93-94`）说明 `sp.together` 的第二位置参数是 `deep` 而非变量，传 `var` 会被引擎静默丢弃——因此 `var` 参数只在 `mode:"apart"` 下有意义。
9. **引擎存在未暴露的算子**：`integrate_multi`、`numeric_matrix`、`moment_generating`、`implicit_function_extremum`、`conditional_check`、`domain_check` 在 `ops.py` 注册表中可用，但 `TOOL_SPECS` 没有对应工具，模型无法通过工具调用它们。
10. **`engine.py` 曾静默裁剪多余参数**（`_call_with_declared_kwargs`，`engine.py:170-196`）：传了算子签名里不存在的参数不会报错。这意味着「参数写错」通常表现为「结果照常返回但没有效果」。**已修复（1.0.2）**：现在会追加 warning「以下参数该算子不接受，已被忽略：…（请检查参数名是否写错）」；排错时仍建议检查返回里的 `input` 字段确认引擎实际收到什么。

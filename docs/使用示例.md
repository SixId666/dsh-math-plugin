# DSH 考研数学一插件 · 使用示例

> 本文所有示例都是**真跑过的**：每段「工具真实返回」都是从引擎里取回的真实输出（只做了字段裁剪，没有改过数值）。
> 每个示例都附了一条「复现」命令，读者可以自己重跑核对。
> *English summary:* Real conversation examples for the four task modes (computation / verification / approach analysis / full solving), all with reproducible commands.

---

## 0. 怎么用：直接在对话里发题

**不需要手动打开插件，也没有开关。** 插件装好之后，DSH 里的模型就多出 14 个数学工具（`math_simplify`、`math_solve`、`math_limit`、`math_derivative`、`math_integrate`、`math_series`、`math_dsolve`、`math_matrix`、`math_probability`、`math_numeric`、`math_vector_calculus`、`math_verify`、`math_analysis`、`math_status`）。你**像平时一样把题目发出来**就行，模型会自己判断这道题该不该算、该调哪个工具、参数怎么填，然后把结果讲给你听。

推荐的说法（措辞随你，模型认的是意图）：

| 你想要什么 | 直接这样说 | 模型通常会做什么 |
| --- | --- | --- |
| **计算** | 「算一下 ∫₀^π x sin x dx」「求 A=[[2,1],[1,2]] 的特征值」 | 调 `math_integrate` / `math_matrix`，给出精确解 |
| **验证** | 「我算的 ∫x eˣdx = x eˣ + eˣ，对不对？」 | 调 `math_verify`，给出通过与不通过**以及错在哪一项** |
| **思路** | 「这题怎么做」「思路是什么」「考点在哪」 | 调 `math_analysis` / `math_series` 等取关键事实，然后**只讲考点与路径，不替你写完** |
| **完整解题** | 「把这道题完整解出来」「按八项完整解」 | 组合 2~3 个工具，按八项结构（题目分析→…→同类识别技巧）交付 |

回答里会区分四件事，别把它们混起来看：

- **计算** = 工具给的精确结果（例如 `pi`、`4/3`、特征值 `3, 1`）；
- **验证** = 工具给的证据等级与反例（引擎每个结果都带 `verification` 字段：`independent` / `cross` / `numeric` / `symbolic+numeric` / `verified` / `partially_verified` / `unverified`），**数值一致不等于解析证明**，工具会明说；
- **思路** = 模型自己的判断（用哪个公式、为什么补面、为什么要分区间），这部分**不会被工具替代**；
- **完整解题** = 计算 + 验证 + 思路的合成，并要求模型给出最终答案和同类题的识别技巧。

三条硬规矩（插件的行为准则，也是本文反例一节的依据）：

1. 像 ∫₀¹x²dx 这种「口算得出」的积分，**也应该**直接调 `math_integrate` 取精确值——但**不允许**为了它去写临时 Python 程序、建文件再执行。
2. 工具返回 `unsolved` / `partial` / `error` 时，模型必须**如实告诉你没算出来/没验证通过**，不许把「未求值」当成「成功」。
3. 什么时候**不该**调用工具：口算题、考查证明思路与定理适用条件的题、几何关系/积分区域/法向量方向这类必须靠数学分析判断的问题。

### 复现方式

本文的「复现」行都写作 `E.execute(op, {...})`，含义是：

```python
import sys; sys.path.insert(0, r"E:\dsh-math\engine")
from mathkit import engine as E, ops          # ops 必须 import，算子才会注册
d = E.execute("integrate", {"expr": "x*sin(x)", "var": "x", "lower": "0", "upper": "pi"})
print(d["status"], d["result"]["text"])       # ok pi
```

在 `E:\dsh-math` 目录下用 `python -X utf8 <脚本.py>` 运行即可。`E.execute` 永不抛异常，失败会体现在 `status`（`ok` / `partial` / `unsolved` / `error`）里。

## 1. A 类：计算

### A1 · 定积分 ∫₀^π x sin x dx

**用户**：算一下 ∫₀^π x·sin x dx 的值。

**模型调用**：`math_integrate(expr="x*sin(x)", var="x", lower="0", upper="pi")`

**复现**：`E.execute("integrate", {"expr": "x*sin(x)", "var": "x", "lower": "0", "upper": "pi"})`

**工具真实返回（节选）**：

```json
{
  "status": "ok",
  "method": "定积分：sp.integrate(expr, (var, a, b))",
  "result": { "text": "pi", "latex": "\\pi", "approx": 3.141592653589793 },
  "conditions": ["被积函数在闭区间 [0, pi]（去掉内部瑕点后）可积"],
  "verification": { "status": "cross",
    "methods": [{ "method": "numeric_integrate 加固数值路线（多路线 + 收敛守卫，与 sp.integrate 相互独立）",
                  "numeric_value": "3.14159", "symbolic_value": "3.14159", "max_rel_dev": 0.0 }],
    "note": "符号结果与独立数值积分（多路线 + 收敛守卫）一致（数值交叉验证，非符号证明）。" }
}
```

**怎么讲给人听**：

- 精确值是 **π**（不是 3.14，也不是「约等于」时就算了）。
- 手算路径：分部积分 ∫x sin x dx = −x cos x + sin x，代入 0 与 π 得 −π·(−1) + 0 = π。
- 工具是符号精确积分，另有一条独立的数值积分路线互相印证（`verification.status = "cross"`，最大相对偏差 0.0）。
- 顺手提醒考点：这是「多项式×三角函数」型分部积分，不定积分部分不要漏 +C。

### A2 · 矩阵特征值与特征向量

**用户**：求矩阵 A = [[2,1],[1,2]] 的全部特征值与特征向量。

**模型调用**：`math_matrix(operation="eigen", matrix="2,1;1,2")`

> 注意：`math_matrix` 的分派参数名是 **`operation`**（取值 `analysis|det|inv|rank|transpose|matmul|matadd|trace|rref|solve_linear|eigen|diagonalize|quadratic|power`），不是 `kind`。示例里 `operation="eigen"` 实际调用引擎的 `eigen` 算子。

**复现**：`E.execute("eigen", {"matrix": "2,1;1,2"})`

**工具真实返回（节选）**：

```json
      { "eigenvalue": "3", "algebraic_multiplicity": 1, "geometric_multiplicity": 1, "eigenvectors": ["[[1], [1]]"] } ],
    "text": "[3, 1]"
  },
  "conditions": ["λ 为 A 的特征值 ⟺ det(λI − A) = 0（特征多项式的根）",
                 "代数重数之和 = 矩阵阶数；几何重数 ≤ 代数重数",
                 "A 为实对称矩阵：特征值全为实数，且存在正交矩阵 Q 使 QᵀAQ = Λ（可用正交对角化）",

  "verification": { "status": "independent", "methods": [
    { "method": "特征多项式重构：∏(λ − λᵢ)^mᵢ 与 charpoly(A) 展开后逐项相同", "agree": true },
    { "method": "迹校验：trace(A) = Σ mᵢλᵢ（用特征值求和，独立于特征多项式）", "expected": "4", "got": "4", "agree": true },

```

**怎么讲给人听**：

- 特征值 **λ₁ = 3，λ₂ = 1**（都是单重，代数量数 = 几何重数 = 1）；特征多项式 (λ−3)(λ−1)。

## 2. B 类：验证（必须能指出错在哪里）

### B1 · 学生给出的原函数是错的

**用户**：我算的 ∫x·eˣ dx = x·eˣ + eˣ + C，帮我验证一下对不对。

**模型调用**：`math_verify(kind="integral", expr="x*exp(x)", candidate="x*exp(x)+exp(x)", var="x")`

**复现**：`E.execute("verify", {"kind": "integral", "expr": "x*exp(x)", "candidate": "x*exp(x)+exp(x)", "var": "x"})`

**工具真实返回（节选）**：

```json
{
  "status": "ok",
  "result": { "passed": false,
    "text": "复核结论：不通过（验证等级：symbolic）；方式：符号差式不为 0，且数值抽样逐点不一致（已给出反例点）",
    "counterexample": "在 {x: -1/2} 处：左边 = -0.303265329856，右边 = 0.909795989569（相对偏差 1.21306）" },
  "verification": { "status": "cross", "passed": false, "level": "symbolic",
    "method": "符号差式不为 0，且数值抽样逐点不一致（已给出反例点）",
    "evidence": {
      "derivative_of_candidate": "x*exp(x) + 2*exp(x)",
      "difference": "-2*exp(x)",
      "numeric": { "agree": false, "max_rel_dev": 1.2130613194252668, "checked_points": 12,
                   "note": "抽样点不一致：{x: -1/2} 处 -0.303265329856 vs 0.909795989569（相对偏差 1.21306）" },
      "finite_difference": { "agree": false, "max_rel_dev": 0.8571428571444826,
                   "note": "中心差分（步长 1/1000000）在 5 个点上与候选导数不一致" } } },
  "warnings": ["复核未通过：在 {x: -1/2} 处：左边 = -0.303265329856，右边 = 0.909795989569（相对偏差 1.21306）"]
}
```

> 上面的 `verification` 是**扁平 `evidence` 视图**的节选；同一对象里还有 `methods` 数组，装着 3 条证据（① 符号比较 `check_antiderivative`；② 高精度数值抽样逐点比较；③ 中心差分独立估计候选原函数的导数），三条 `passed` 全为 `false`。讲给人听时按「三条证据逐一」说，比只报一个「不通过」有力得多。

**怎么讲给人听**（要点：不许只说「错了」）：

- **结论：不通过**，错在候选里的 **+eˣ 这一项是多余的**。
- **证据链**：对候选求导得 `x*eˣ + 2eˣ`，比被积函数 `x·eˣ` **多出 2eˣ**；差式化简为 `-2*eˣ ≠ 0`；再拿一个具体点 {x = −1/2} 做数值对照：被积函数 −0.3033 vs 候选导数 0.9098，相对偏差 1.21。
- **正确结果**：∫x eˣdx = (x−1)eˣ + C。把候选的 +eˣ 改成 −eˣ 就对了——这个改动可以立刻再验一次：`math_verify(kind="integral", expr="x*exp(x)", candidate="x*exp(x)-exp(x)", var="x")` → `passed: true`，`difference: "0"`，12 个抽样点全部一致。
- 提醒：验证等级是 `symbolic`（有符号证据），通过时工具仍会注明「数值抽样仅为数值证据，不是符号证明」——把这句话一起转述，别过度承诺。

### B2 · 微分方程候选通解多了一项

**用户**：微分方程 y′ − 2y = 0 的通解，有人写的是 C₁e²ˣ + x，你检查一下。

**模型调用**：`math_dsolve(mode="check", equations=["y' - 2*y = 0"], candidate="C1*exp(2*x)+x", funcs=["y"])`

**复现**：`E.execute("ode_check", {"equations": ["y' - 2*y = 0"], "candidate": "C1*exp(2*x)+x", "vars": ["x"], "funcs": ["y"]})`

**工具真实返回（节选）**：

```json
{
  "status": "partial",
  "result": { "text": "残差不为 0：候选解不满足原微分方程",
    "residuals": ["1 - 2*x",
      "（数值抽样判定：different；抽样点不一致：{x: 1/3} 处 0.333333333333 vs 0；{x: 2/3} 处 -0.333333333333 vs 0；{x: 3/2} 处 -2 vs 0）"] },
  "verification": { "status": "independent",
    "methods": [{ "method": "独立机制：把候选解代入原方程并化简残差（不依赖 sp.dsolve 的求解过程）", "agree": false,
                  "residuals": ["1 - 2*x", "（数值抽样判定：different；抽样点不一致：{x: 1/3} 处 0.333333333333 vs 0；{x: 2/3} 处 -0.333333333333 vs 0；{x: 3/2} 处 -2 vs 0）"] }],
    "note": "已独立判定该候选解是错误的（残差非 0），这属于「验证失败」而非「未能验证」。" },
  "warnings": ["候选解未通过代回验证，残差见 extra.residuals。"]
}
```

**怎么讲给人听**：

- **结论：不满足方程**，错在**多加的 x 这一项**，而且错得很清楚：y′−2y 化简后是 **1 − 2x**，不是 0（x = 1/3 处是 1/3，x = 3/2 处是 −2，都不为 0）。
- **为什么会这样**：C₁e²ˣ 本身确实是 y′−2y=0 的解（把候选换成 `C1*exp(2*x)` 再验一次 → 残差 `"0"`）；但加上 x 后，y′−2y 里就多出 1−2x。
- **正确通解**：y = C₁e²ˣ（一阶方程只有一个任意常数；写成 C₁e²ˣ + x 等于把「特解」当成了齐次解）。
- **务必注意 `status`**：这次是 `partial` 而不是 `error`——它是「**验证失败**」而不是「没能验证」。工具的原话是「已独立判定该候选解是错误的（残差非 0），这属于「验证失败」而非「未能验证」」；讲题时说清楚：**有证据地判定不成立**，不是「算不动」。

## 3. C 类：思路分析（不直接给答案）

### C1 · 定义域型题目

**用户**：这题怎么做——求 f(x) = x²·ln x 的定义域，解答时要注意什么？

**模型调用**：`math_analysis(mode="domain", expr="x^2*log(x)", var="x")`

**复现**：`E.execute("domain", {"expr": "x^2*log(x)", "var": "x"})`

**工具真实返回（节选）**：

```json
{
  "status": "ok",
  "result": { "domain": "(0, +∞)", "intervals": ["(0, +∞)"], "domain_text": "(0, +∞)",
    "restrictions": ["对数真数 _w_domain > 0 → Interval.open(0, oo)"],
    "continuous_domain_note": "sp.continuous_domain 交叉核对得到 Interval.open(0, oo)" },
  "verification": { "status": "partially_verified", "methods": [
    { "method": "定义域内逐点代入检验（要求有限实数值）", "agree": false,
      "note": "定义域内抽样 0 点全部取到有限实数值" },
    { "method": "sp.continuous_domain 独立交叉核对", "agree": true,
      "note": "sp.continuous_domain 交叉核对得到 Interval.open(0, oo)" }] }
}
```

**怎么讲给人听**（讲思路，别把题目讲完）：

- **考点**：初等函数的定义域约束——对数要求真数 > 0。
- **路径**：先看 x² 是整式（全体实数）；再要求 x > 0；取交集得 **(0, +∞)**，是**开区间**。
- **易错点**：① 容易漏掉 x ≠ 0（此处被 x>0 涵盖）；② 讨论单调性/极值时不能把 x ≤ 0 的部分写进去；③ 求完极值点要检查它是否落在定义域内。
- **诚实地说工具没做什么**：这次验证等级是 `partially_verified`，因为「定义域内抽样」那条复核在 **0 个抽样点**上执行（工具自己写明「定义域内抽样 0 点」）——也就是这条证据其实是空的，别把它说成「已充分验证」。
- 思路题的规矩：模型只给考点与路径、提示你下一步该算什么；具体计算结果由你自己动手（或你明确要求「完整解出来」时再算）。

### C2 · 级数敛散性的思路

**用户**：判断级数 Σ_{n≥1} n/2ⁿ 的敛散性，这题思路是什么？

**模型调用**：`math_series(mode="sum", expr="n/(2^n)", var="n", lower="1", upper="oo")`，并用 `math_numeric(mode="sum", expr="n/(2^n)", var="n", lower="1", upper="oo")` 做数值侧写

**复现**：
`E.execute("sum", {"expr": "n/(2^n)", "var": "n", "lower": "1", "upper": "oo"})`
`E.execute("numeric_sum", {"expr": "n/(2^n)", "var": "n", "lower": "1", "upper": "oo"})`

**工具真实返回（节选）**：

```json
// sum（精确求和）
{ "status": "ok", "result": { "text": "2", "latex": "2", "approx": 2.0 },
  "verification": { "status": "independent+numeric", "methods": [
    { "method": "mpmath.nsum 收敛加速独立数值求和（数值证据，非收敛性证明）", "independent": true, "agree": "equal",
      "detail": "mpmath.nsum（收敛加速）独立数值求和 = 2.0，与符号结果 2.0 的相对偏差 0.000e+00（数值证据，不构成收敛性证明）" }],
    "note": "级数求和没有纯符号的独立证明手段：本结果由 mpmath 的独立数值求和（收敛加速）给出数值证据；收敛性判定仍依赖 sp.summation 的符号结论。" } }

// numeric_sum（数值侧写）
{ "status": "ok", "result": { "text": "2.00000000000000",
    "abs_error": 4.2338863081839495e-60,
    "chosen_route": "部分和(200 项) + Euler–Maclaurin 尾项（∫_N^∞ − f(N)/2 − f'(N)/12 + f'''(N)/720 − …）",
    "suspected_closed_form": "2" },
  "verification": { "status": "numeric",
    "methods": ["mpmath.nsum method='r'（Richardson 外推）", "mpmath.nsum method='s'（Shanks 变换）",
                "mpmath.nsum method='d'（直接求和）", "部分和(200 项) + Euler–Maclaurin 尾项"],
    "note": "数值求和：采用「部分和(200 项) + Euler–Maclaurin 尾项（∫_N^∞ − f(N)/2 − f'(N)/12 + f'''(N)/720 − …）」= 2.0，各路线最大偏差 0.0，误差界 4.2338863081839495e-60。**数值加速只对收敛级数有效**，发散级数的任何截断和都没有意义；结论不构成解析证明。" } }
```

**怎么讲给人听**：

- **考点**：数项级数求和/敛散性——比值判别法、幂级数逐项求导法（Σxⁿ 求导）。
- **路径 A（判别敛散）**：比值判别法 lim |a_{n+1}/a_n| = lim (n+1)/(2n) = 1/2 < 1 → **收敛**（这一步是论证，工具不替你做）。
- **路径 B（求和）**：已知 Σxⁿ = x/(1−x)（|x|<1），逐项求导得 Σn x^{n−1} = 1/(1−x)²，令 x = 1/2 得 Σ n/2ⁿ = 2。
- **工具位置**：`sum` 给出精确和 2；`numeric_sum` 用「200 项部分和 + Euler–Maclaurin 尾项」得到 2.00000000000000、误差界 4.23e−60，并把 2 列为 `suspected_closed_form`。
- **必须说清的两句**：① 数值侧写**只对已收敛的级数**有意义，它**不能**用来证明收敛——敛散性判断必须落回比值判别法等定理；② 工具自己也声明「级数求和没有纯符号的独立证明手段……收敛性判定仍依赖 sp.summation 的符号结论」（原话见 `verification.note`），所以这里的验证等级是 `independent+numeric` 而不是 `independent`，别把它讲成「已被符号级独立证明」。

## 6. 常见追问的处理（代价最小原则）

总原则：**先判断这次追问是否真的改变了数学对象**。只变了「不影响结论的呈现方式」就不重算；一旦题面条件变了，只重算**依赖该条件的那一段**，不要从头把链条全跑一遍。

### 追问 1 · 「换个数再算」

**用户**：那如果上限是 π/2 呢？

**处理**：同一个被积函数、只换了积分上限 → 只需**一次** `math_integrate`。

- 调用：`math_integrate(expr="x*sin(x)", var="x", lower="0", upper="pi/2")`
- 复现：`E.execute("integrate", {"expr": "x*sin(x)", "var": "x", "lower": "0", "upper": "pi/2"})`
- 真实返回：`result.text = "1"`，`approx = 1.0`，`verification.status = "cross"`。
- 讲法：**结果从 π 变成 1**；原函数 sin x − x cos x 不变，只是代入端点不同（sin(π/2) − (π/2)cos(π/2) = 1）。不需要重算不定积分部分，也不需要重跑任何验证——变的只是一个代入值。

### 追问 2 · 「矩阵换个元素」

**用户**：那 A = [[2,1,1],[1,2,1],[1,1,2]] 呢？

**处理**：矩阵变了 → 需要重新调用，但**一次调用就能拿到全部汇总量**，不要为 det、rank、trace、特征值分别调用。

- 调用：`math_matrix(operation="analysis", matrix="2,1,1;1,2,1;1,1,2")`
- 复现：`E.execute("matrix_analysis", {"matrix": "2,1,1;1,2,1;1,1,2"})`
- 真实返回：`det_text = "4"`，`rank = 3`，`trace_text = "6"`，`eigenvalues = ["4", "1"]`，`algebraic_multiplicities = [1, 2]`，`characteristic_polynomial = "(lambda - 4)*(lambda - 1)**2"`，`verification.status = "independent"`（内部用秩判据与谱关系交叉印证）。
- 讲法：det = 4 ≠ 0 → 可逆、满秩；特征值 4（单重）、1（二重）；可自检 trace = 6 = 4+1+1 ✓，det = 4 = 4×1×1 ✓。
- **如实交代工具的未完成项**：该返回里 `"not_computed": ["eigenvectors"]`、`"eigenvectors_note": "未计算：特征向量求解失败（ValueError: not enough values to unpack (expected 4, got 3)）"` —— 汇总视图**没算特征向量**（这是引擎里一处真实的能力缺口）。要特征向量请单独调用 `math_matrix(operation="eigen", matrix=…)`；如果那也失败，就明确告诉用户「工具没能给出特征向量」，然后用秩与重数自行判断（1 是二重特征值，需解 (A−I)x=0 得二维特征子空间）——**不要把没算出来的东西说成算出来了**。

### 追问 3 · 「这个结果我不确定 / 换一种方法验证」

**用户**：4/3 这个数我不太确定，能用别的方法再验证一遍吗？

**处理**：不要在同一个算子里反复按「再来一次」（那只是重复同一条推理）。要换**验证机制**：

- 与 `math_verify` 组合：把结果作为 `candidate` 交出去，让验证器用**独立机制**（符号差式化简、代回残差、特征多项式代入、独立数值抽样）复核。
- 与 `math_numeric` 组合：数值路线与符号路线是**两套实现**，符号结果 → 数值复核（见 S3、S4）。
- 与定义法组合：公式法算完，再用定义法算一遍（见 D2 的格林公式 ↔ 参数化第二类曲线积分，2/3 + 2/3 = 4/3）。
- 关注返回里的 `verification.status` 而不是 `status`：`ok` 只表示算出来了，`verification.status` 才表示证据等级（`independent` / `cross` / `numeric` / `symbolic+numeric` / `verified` / `partially_verified` / `unverified`）。**`unverified` 就意味着「工具自己没验过」**，此时必须另找一条路，而不是告诉用户「已验证」。
- 讲法模板：「工具算出来是 X，验证等级是 Y；因为 Y 只是数值一致/内部复核失败，我又用 Z 方法独立算了一遍，得到 X′，两者一致（或差异多少、原因是什么），所以结论是……」。

### 追问 4 · 「题目里有个条件变了」

**用户**：如果把 L 改成顺时针方向呢？如果把上边界从 y = 1 改成 y = 2 呢？

**处理**：**先看这个条件影响哪一步**，再决定重算哪一段。

- 变方向（正向 ↔ 负向）：区域的二重积分值不变，只是**符号**取反。
  - 调用：`math_vector_calculus(mode="green", expr="2*x*y-x^2", expr2="x+y^2", x_lower="-1", x_upper="1", y_lower_expr="x^2", y_upper_expr="1", orientation="negative")`
  - 真实返回：`result.text` **仍然是 "4/3"**（工具返回的是 ∬_D 的值），负号只出现在 `conditions`（"L 取负向时 ∮_L P dx + Q dy = −∬_D (Q_x − P_y) dx dy"）与 `warnings`（"用户声明 L 为负向（顺时针）：格林公式结果为上式取负号。"）里。
  - 讲法：**这里必须由模型自己把符号加上**——∮ = −4/3。直接把 `text` 抄给用户就错了。这类「工具给了绝对值、定向信息在说明里」的情况，要按说明补符号。
- 变区域（上边界 y = 1 → y = 2）：**必须重算**，因为区域 D 变了。
  - 调用：`math_vector_calculus(mode="green", expr="2*x*y-x^2", expr2="x+y^2", x_lower="-1", x_upper="1", y_lower_expr="x^2", y_upper_expr="2")`
  - 真实返回：`result.text = "10/3"`（≈3.3333333333333335），`verification.status = "independent"`（非矩形区域，复核为 mpmath 数值二重积分）。
  - 讲法：∫_{−1}^{1}(1−2x)(2−x²)dx = ∫_{−1}^{1}(2−x²)dx = 4 − 2/3 = 10/3，可以顺手口算核对——手算与工具结果一致。
- 只变变量名/写法（如把 `y'` 写成 `diff(y(x),x)`）：**不必重算**，`math_dsolve` 两种写法都接受（工具说明里明确写了），这类追问直接沿用已有结果即可。

## 7. 反例：这三种情况**不该**调用工具

（依据插件行为准则：「不需要调用的情况：可以口算或直接套用基础公式的简单算式；题目考查的是证明思路、定理适用条件或解题策略而不是具体计算；几何关系、积分区域、法向量方向这类必须靠数学分析判断的问题。」）

### 反例 1 · 纯口算/基础公式题

**用户**：2³ × 2⁵ 等于多少？/ 求 (x²)′ ？

**为什么不调用**：这是可以口算或直接套用基础公式的算式，调用工具只是把「调用成本」换成了「零收益」，还会让回答变慢、变啰嗦。**正确处理**：直接回答 2⁸ = 256、2x。

**注意边界**：这条**不**适用于稍复杂但仍有闭式的积分——插件明确要求「像 ∫₀¹x²dx 这样的积分也应直接调用 `math_integrate` 取得精确结果」，但**同时禁止**为了它去写临时 Python 程序、建文件再执行。也就是说：**该用工具就用工具，不该写程序就别写程序**。

### 反例 2 · 考查证明思路、定理适用条件的题

**用户**：证明：若 f 在 [a,b] 上连续、在 (a,b) 内可导且 f(a)=f(b)，则存在 ξ 使 f′(ξ)=0。（要求写证明）

**为什么不调用**：题目要的是**证明的构造与定理适用条件的说明**（罗尔定理的三个条件各用在哪里、ξ 的存在性从何而来），不是数值结果。这里没有任何「待求的精确值」，调 `math_verify` 也无从下手——它验证的是具体表达式/方程的结果，不是「证明过程是否严格」。

**正确处理**：模型自己写证明，并讲清考点：连续性保证最大值最小值取到，可导性保证 Fermat 引理可用，f(a)=f(b) 保证极值不在端点。相关的「为什么不能少任何一个条件」也属于思路，必须留在推理里。

（同理：判断 `Σ1/n^p` 敛散性要讲 p-级数判别法与比较判别法的适用性时，先讲论证；数值侧写只能作为**辅助**，而且必须说明它不构成敛散性的证明。）

### 反例 3 · 几何关系 / 积分区域 / 方向判断

**用户**：曲面 Σ 是上半球面，用它算第二类曲面积分时，法向量该取外侧还是内侧？要不要补面？这个积分区域怎么投影？

**为什么不调用**：**选哪个公式、补不补面、朝哪个方向投影、区域怎么分块**，都是数学分析判断，工具只能算你**已经定好**的那个积分。插件对 `math_vector_calculus` 写得很明确：「考研中格林/高斯/斯托克斯公式的选择（曲面是否封闭、投影区域是否简单、被积函数是否轮换对称、补面还是直接投影）属于数学分析判断，必须先由你判断并说明理由，再用本工具计算已选定的那个积分」；「还没决定用投影法还是高斯公式……这些必须保留在推理里，不能交给计算器代替。」

**正确处理**：模型先做判断并说明理由——例如「Σ 不封闭 → 补上底面圆盘使其封闭，外侧定向 = 补面取**下**侧（内法向），因此封闭曲面上的积分要**减去**补面上的积分」——判断做完、区域和方向都明确之后，**再用** `math_vector_calculus(mode="gauss"|"surface", …)` 把两个积分分别算出来。顺序不能颠倒。

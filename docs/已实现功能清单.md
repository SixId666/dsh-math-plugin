## 1. 运行依赖（交付物 3）

### 1.1 DSH 侧（Host 插件）

| 依赖 | 版本/说明 |
| --- | --- |
| DeepSeek Harness | 本机桌面版（desktop profile，宿主 `@deepseek-ai/dsh` + `@deepseek-ai/dsh-app-boot`） |
| Node.js | 由 DSH 自带运行时提供（插件以 ESM 形式被宿主 loader 加载） |
| 外部 npm 依赖 | **无**。`plugin/lib/*.js` 只使用 Node 内置模块（`node:os` / `node:path` / `node:url` / `node:fs` / `node:child_process` 经宿主 `subprocess` 服务） |

插件**刻意不导出 Config schema**（`plugin/lib/entry.js:31` 注释）：DSH 的 Config 描述依赖
`@deepseek-ai/schemastery`，而 linked bundle 在本构建里解析不到宿主包，因此配置项由插件自行归一化：
`python` / `workerPath` / `timeoutMs`（默认 60000）/ `cache`（默认 true）。

### 1.2 Python 侧（计算引擎）

| 依赖 | 必需 | 用途 |
| --- | --- | --- |
| Python | 是（3.10+，实测 3.13.5） | 常驻引擎进程 |
| `sympy` | 是（实测 1.13.3） | 符号计算、方程求解、微积分、线代、概率的解析式 |
| `mpmath` | 是（实测 1.3.0） | 任意精度数值求积/求根，作为独立数值验证路线 |
| `numpy` | 否 | 大矩阵、数值线性代数加速 |
| `scipy` | 否 | 数值积分/优化/求根的补充路线 |

导入策略：`engine/mathkit/numeric.py` 对 numpy/scipy **在函数内惰性导入**，缺失时退化到 mpmath 路线，
不会因未装 scipy 而整体不可用。引擎不执行任何 shell 命令、不写临时文件、不联网。

Python 解释器解析顺序见 [plugin/README.md](../plugin/README.md#1-环境要求)（环境变量 → PATH → 已知安装位置）。
本机实测解析到 `E:\anaconda3\python.exe`。

## 2. 架构

```
DSH 对话
  └─ Agent 调用 math_* 工具（Host 插件注册，tool calling）
       └─ plugin/lib/tools.js      参数 → (op, args) 映射
       └─ plugin/lib/bridge.js     PythonBridge：常驻子进程 + 请求超时 + 结果账本/缓存
            └─ engine/worker.py    JSON lines over stdio（{id, op, args} ↔ {id, status, …}）
                 └─ engine/mathkit/ 算子实现（214 个）
                      ├─ ast.py            表达式解析/规范化（^ → **、隐式乘法、关系运算符、函数白名单）
                      ├─ sympy_core.py     共用工具（化简、数值比较、闭式判定）
                      ├─ result.py         统一返回结构 MathResult（status/conditions/verification/…）
                      ├─ engine.py         注册表 op()、参数别名、签名裁剪、超时保护
                      ├─ calculus.py       极限/导数/积分/级数/ODE
                      ├─ linalg.py         行列式/逆/秩/特征值/对角化/二次型/线性方程组
                      ├─ numeric.py        高精度数值（三道路线守卫）
                      ├─ probability.py    分布/期望方差/协方差/贝叶斯/联合边缘
                      ├─ probability_extra.py 参数估计/区间估计/假设检验/中心极限定理/抽样分布
                      ├─ symbolic_extra.py 多元微分/隐函数/极值/拉格朗日/不等式/函数分析
                      ├─ vector_calc.py    曲线曲面积分与三大公式
                      └─ verifier.py       独立验证（导数复核、代回残差、条件域检查）
```

设计要点：

1. **计算与验证分离**：主结果由 `calculus/linalg/…` 产出，验证由 `verifier.py` 及每个算子内部的
   `r.verify(...)` 用**不同途径**完成（求导回代、代回方程、矩阵乘积、归一化、mpmath 求积、矩母函数等）。
2. **未求得绝不冒充成功**：`ast.is_unevaluated()` 拦截 SymPy 原样回显的未求值对象；`status` 严格区分
   `ok / partial / unsolved / error`。
3. **失败也记账**：`engine/worker.py:56 Cache` 同时保存成功缓存与失败记录，避免相同参数的无意义重试。

## 3. 暴露给 DSH 的 14 个工具

| 工具 | 引擎算子（主分派） | 覆盖能力 |

| `math_probability` | `probability` / `distribution` / `expectation` / `variance` / `covariance` / `correlation` / `joint_marginal` / `distribution_moments` / `distribution_from_pmf` / `point_estimate` / `interval_estimate` / `hypothesis_test` / `sampling_distribution` / `central_limit` | 概率计算、分布、数字特征、贝叶斯、估计与检验、中心极限定理 |

## 5. 已实现的机制（对应规格各章）

| 规格条目 | 实现 |
| --- | --- |
| 五、统一返回结构 | `engine/mathkit/result.py` 的 `MathResult`：`success / status / operation / input / result / conditions / verification / method / error / warnings / elapsed_ms`；`status ∈ {ok, partial, unsolved, error}` |
| 五、不得把未求值表达式当成功 | `ast.is_unevaluated()` + 各算子对 `C.is_closed_form()` 的检查；`_test_special.py` 测试 3 专门断言 |
| 六、防重复计算 | 成功缓存 + 失败记账（`worker.py:56`），键 = 算子 + 全部参数（含表达式规范化结果、变量、上下限、极限方向、精度） |
| 六、默认只执行一次 | 账本拦下完全相同的失败参数；只有改参数/换方法或显式 `retry: true` 才重试（`entry.js` 每个工具都带 `retry` 参数） |
| 六、引擎崩溃限制重启 | `bridge.js` 的 `MAX_AUTO_RESTARTS = 2` |
| 八、图片识别 | 交给 DSH 原生多模态（`read_image` / `modlens_read_image`）转文本；插件不做 OCR，限制见 [未实现与限制.md](未实现与限制.md) |
| 九、对话连续性 | 工具描述与系统提示要求复用已验证结果、条件变化时重检、不同题不混用缓存 |
| 十、Token 优化 | `render.js` 的 `RESULT_SKIP` 去重、验证段落集中渲染、`math_status` 一次返回引擎全貌 |
